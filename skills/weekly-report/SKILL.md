# 周报与月报

使用 [周报模板](references/weekly-template.typ) 或 [月报模板](references/monthly-template.typ) 和 [渲染脚本](scripts/render.py) 生成周报或月报, 脚本按报告类型选择模板. 保留模板中的 A4 页面宽度, 字体, 字号, 页边距, 标题, 信息行和类别表格. 页面高度随内容自动增长, 一次渲染只输出一张图片.

## 前提条件

+ 运行时: Python 3.9 或更高版本, 用于运行渲染脚本. 检查: `python3 -V`; 命令不存在或状态非零按缺失处理, 版本低于 3.9 也按缺失处理.
+ 第三方依赖: 无, 渲染脚本只使用 Python 标准库. 检查: `true`; 以状态 0 退出表示本项没有需要安装或导入的包.
+ 外部程序: Typst 0.13 或更高版本, 用于编译 Typst 源文件. 检查: `typst --version`; 命令不存在或状态非零按缺失处理, 版本低于 0.13 也按缺失处理. 脚本会再次实际检查 Typst 版本.
+ 认证: 无. 检查: `true`; 以状态 0 退出表示本项没有需要检测的认证.
+ 字体: 模板只使用 `Alimama FangYuanTi`. 检查: `typst fonts | grep -i Alimama`; 未匹配时说明字体缺失. 字体缺失不阻断渲染: 脚本回退到 Typst 默认字体继续渲染, 并通过结果中的 `font_note` 返回提示, 交付时告知用户中文字形可能与预期不同.
+ Python 或 Typst 检查不满足时停止, 不继续产出, 报告按五段给出: 缺少项, 检测结果, 要求, 修复命令, 影响. 字体缺失不属阻断项, 按上一条回退并提示.
+ 检查命令按 POSIX shell (sh/bash) 编写. 字体检查使用管道与 `grep`, 其他 shell 中改为直接运行 `typst fonts` 并查找 Alimama. 以 `true` 作为检查命令的条目表示该项无要求, 在不支持 `true` 的 shell 中直接视为通过.

## 工作流程

### 1. 收集内容

+ 类型: 周报或月报.
+ 年份和月份: 整数. 未提供时使用用户当前日期, 并在交付时说明. 语境存在歧义时先确认.
+ 第几次: 仅周报需要, 表示当月第几次周报, 正整数. 月报没有此字段.
+ 姓名和学号: 可省略. 省略时使用默认值 `易靖远` 和 `26031210039G`, 提供时覆盖默认值.
+ 日期范围: 起止日期, 如 2026.3.2 至 2026.3.8. 周报通常为一周, 月报通常为整月.
+ 实验室、项目贡献条目和科研进展条目: 用户提供的非空条目列表. 事实层原样保留: 人名, 项目名, 文档名, 数字与进度表述与用户提供的一致, 条目的数量, 顺序和条目内换行不变. 表述层按下方 "条目表述" 整理成事项式陈述.
+ 其他: 实验室其他服务性工作, 运动情况, 心得体会, 反思教训四项内容, 没有时填 无.

#### 条目表述

事实层是硬约束, 表述层允许按汇报口吻规范化. 条目按下列方式呈现:

+ 一条一个动作, 动词开头, 省略主语, 执行者默认为报告人. 不出现 "我", "我们", "本人".
+ 不写 "本周", "本月", "最近" 这类周期词; 需要精确到时间时写叙述中给出的具体日期.
+ 只陈述做了什么, 不描述过程, 心情, 难度与耗时, 不加 "顺利完成", "积极推进" 这类自我修饰.
+ 条目末尾不加句号, 条目内部用逗号.
+ 用户提供的条目若已是事项式陈述, 保持其表述, 不为套用风格而改写.
+ `实验室其他服务性工作`, `运动情况`, `心得体会`, `反思教训` 四项采用同一口吻, 但不强行动词开头; 已是名词短语或 `无` 时按原短语呈现, 如 `日常锻炼` 不改成 `进行日常锻炼`.
+ 风格取舍与事实准确或可读性冲突时, 以后两者优先.

口语叙述与条目的对照:

| 口语叙述 | 照抄口语 | 条目 |
| --- | --- | --- |
| 我这周跟师兄聊了下大论文的选题 | 我这周跟师兄聊了下大论文的选题 | 讨论大论文选题 |
| 我花了两天才跑通接口, 挺折腾的 | 我花了两天才跑通接口, 挺折腾的 | 推进实验平台接口开发 |
| 最近在整理 3 篇文献, 大概完成七八成 | 最近在整理 3 篇文献 | 整理 3 篇文献, 完成七八成 |
| 本周把数据集标注完了, 顺利完成 | 本周把数据集标注完了 | 完成数据集标注 |
+ 考勤: 平均打卡时长(小时)和上午 9:30 前打卡次数.
+ 自我评价: 非常满意, 满意或不太满意三选一.

仅类型, 月份, 各类内容或考勤等缺失时, 使用当前环境的询问工具或直接追问. 不因为年份缺失重复询问. 将明确的年份和月份一并传给脚本, 避免执行机器与用户日期不同.

### 2. 运行渲染脚本

按 "前提条件" 节完成检查后再运行. 字体缺失时按该节说明回退, 不阻断渲染.

输入 JSON 包含以下字段. `name` 和 `student_id` 可省略, 省略时分别使用 `易靖远` 和 `26031210039G`. `nth` 仅周报需要. `attendance_hours` 与 `attendance_early` 可写数字或非空字符串. 其余文本字段均为非空字符串, `contributions` 与 `research` 为非空字符串数组. 使用 JSON 序列化工具保存内容, 不手工拼接用户文本到 shell 命令或 Typst 标记中.

```json
{
  "kind": "周报",
  "year": 2026,
  "month": 3,
  "nth": 2,
  "name": "易靖远",
  "student_id": "26031210039G",
  "start": "2026.3.2",
  "end": "2026.3.8",
  "contributions": ["查看和对比实验室主机的硬件设备"],
  "research": ["阅读师兄师姐的大论文, 积累综述的素材"],
  "service": "无",
  "exercise": "日常锻炼",
  "reflection": "无",
  "lesson": "无",
  "attendance_hours": 5.5,
  "attendance_early": 5,
  "self_evaluation": "满意"
}
```

把输入保存到临时 JSON 文件, 使用本 skill 中脚本的实际路径运行:

```bash
python3 /path/to/weekly-report/scripts/render.py --input /path/to/input.json --output-dir /path/to/output
```

+ 输出目录默认当前目录. 脚本将输入转为经过转义的 Typst 字符串, 不执行条目中的代码或标记.
+ 先在临时目录编译图片并检查尺寸, 成功后交付. 编译失败时显示错误, 不留下部分报告产物, 不静默改用其他方案.
+ 已有相同报告的源文件或图片时报告冲突, 不覆盖. 告知用户现有路径, 使用用户指定的新目录或由用户先处理原文件. 发布阶段的同名冲突同样以中文错误停止, 不覆盖.

### 3. 核对并交付

+ 周报产物为 `weekly-report-2026年3月第2次.png`, 月报为 `monthly-report-2026年3月.png`, 两者都只输出一张 PNG 和同名 `.typ`, 没有页码后缀.
+ 源文件包含模板和完整数据, 可独立编译, 不依赖临时 JSON 或 skill 安装路径.
+ 图片宽度为 A4 300 DPI 的 2480 像素, 高度随内容自动变化. 不通过缩字, 截断, 分页或改写条目控制尺寸.
+ 表述核对: 条目不含第一人称 ("我", "我们", "本人") 与周期词 ("本周", "本月", "最近"); 人名, 项目名与数字与用户提供的一致; 条目数量与顺序与用户叙述一致.
+ 使用当前环境的图像查看工具检查图片, 确认标题, 信息行, 表格边框, 中文字形, 自我评价复选框和各类别内容完整.
+ 字体缺失而回退字体时, 自我评价的方框与勾形状不变, 三个选项的标记粗细一致.
+ 汇报 PNG 路径, Typst 源文件路径, 实际使用的默认年月, 以及超长图片的高度. 最终产物只包含 `.png` 和 `.typ`, 临时输入不作为交付物.
+ 结果中的 `font_note` 非空时, 在交付说明里告知用户已回退字体, 中文字形可能与预期不同.

需要重新编译已交付源文件时, 输出路径直接使用同名 PNG:

```bash
typst compile "weekly-report-2026年3月第2次.typ" "weekly-report-2026年3月第2次.png" --format png --ppi 300
```

## 操作边界

+ 事实层是硬约束: 人名, 项目名, 文档名, 数字, 进度表述和条目数量与顺序一律来自用户, 不虚构, 补写结论或评价. 用户只叙述做过的事时, 不加 "取得进展", "显著提升" 这类原文没有的结论.
+ 表述层允许按 "条目表述" 规范化: 可省略主语, 去掉周期词, 过程与情绪描述及自我修饰, 但不改动事实, 不合并或拆开独立事项.
+ 用户未要求时不修改模板版式, 表格结构, 字体或页面尺寸.
+ 编译失败时报告完整错误及原因, 不把失败或部分产物报告为成功.
