# Agent Skills 规范

本文件汇总 [Agent Skills 规范](https://agentskills.io/specification) 定义的硬约束, 作为 skill-creator 创建和校验 skill 时的唯一规则来源.

标准只约束目录形状和 `SKILL.md` 的 frontmatter. 正文格式, 脚本语言, 加载时机, 调用方式和分发格式由各客户端自行决定, 不属于标准.

## 目录结构

一个 skill 是一个目录, 至少包含 `SKILL.md`:

```text
skill-name/
|-- SKILL.md          # required: metadata + instructions
|-- scripts/          # optional: executable code
|-- references/       # optional: docs loaded on demand
|-- assets/           # optional: templates, images, data
`-- ...               # additional files or directories
```

+ `SKILL.md` 是入口. 客户端在激活 skill 时读取完整正文.
+ `scripts/`, `references/` 和 `assets/` 是标准推荐的约定目录, 不是必需的.
+ 标准允许目录中出现其他文件或子目录. 它们是否被加载或执行取决于客户端.
+ 目录名必须与 frontmatter 的 `name` 相同 (双方按 NFKC 归一化后比较).

最小 `SKILL.md`:

```markdown
---
name: skill-name
description: 说明这个 skill 做什么, 以及何时使用.
---

## 前提条件

+ <运行时名称与最低版本>.
  检查: `<可执行的版本检查命令>`
+ <第三方依赖包; 无依赖时写 无>.
  检查: `<可执行的依赖检查命令>`
+ <外部程序与认证; 没有时写 无>.
  检查: `<可执行的检查命令>`

## 流程

1. 读取必要输入.
2. 按步骤执行并输出结果.
```

示例中的 `## 前提条件` 是本流程的强制项, 不是 Agent Skills 标准的要求: 标准只约束目录形状和 frontmatter, 最小示例保留该节是为了与下文要求一致. 新建或改进 skill 时按实际运行时, 依赖, 外部程序和认证填写, 不能删掉这一节, 也不要保留占位符交付.

## 运行前提

skill-creator 及其产出的 skill 用 `SKILL.md` 的 `## 前提条件` 一节声明整个 skill 所有执行路径需要的运行时, 最低版本, 第三方依赖, 外部程序和认证; 不能只列当前请求用到的项. 该要求适用于 skill-creator 自身, 以及本流程新建或改进的 skill; 未改动的既有 skill 不因本次规范更新而回溯强制补上该节, 但下次改进该 skill 时必须补上. 每个条目给出可执行的检查命令. 检查命令按目标平台书写; 平台不唯一时明确所用 shell, 并在需要时给出等价命令 (例如 POSIX shell (sh/bash) 与 Windows PowerShell). 命令的脚本自身路径按执行时所在目录书写; 命令指向 skill 内部其他文件或依赖目录时, 路径以 skill 目录为基准书写. 执行时脚本按自身位置解析 skill 内部路径, 不以当前工作目录作为 skill 内部路径的解析基准. 文档同时给出在 skill 目录内与其他目录下的正确写法. 已安装版本低于要求时按缺失处理.

需要安装第三方依赖时, 安装依赖所用的包管理器 (例如 `npm`) 同样属于外部程序, 必须列入 `## 前提条件` 并给出可执行的检查命令; 命令不存在时按缺失处理. 这是本流程对 skill 的要求, 不是 Agent Skills 标准对 skill 的强制项, 写作时不要把它表述为标准要求.

检查顺序: 运行时 → 版本比较 → 依赖目录 → 包可导入 → 外部程序与认证. 任一项不满足时停止执行, 不继续产出, 并按五段报告: 缺少项, 检测结果, 要求, 修复命令, 影响. 随后询问用户选择修复后继续, 授权降级或终止; 没有降级路径时只提供修复和终止. 用户未选择前不继续, 不默认降级.

第三方依赖只按 `## 前提条件` 列出的清单安装. skill 可以在自身目录创建依赖目录并按需安装, 但不能把 `package.json`, 锁文件或其他依赖清单提交到仓库. 依赖目录存在但包缺失时可以直接安装; 安装失败按前提缺失处理并报告原始错误. 修复命令执行成功后重新执行本节的全部前提检查 (运行时, 版本比较, 依赖目录, 包可导入, 外部程序与认证); 全部通过后才继续执行, 重新检查仍失败时按安装失败处理并重新阻断. 依赖目录以外的路径不被自动修改.

分发 skill 时排除 `node_modules` 等依赖目录, 不要把依赖目录打进分发产物; 使用者在目标环境按 `## 前提条件` 重新安装依赖, 不复制依赖目录代替安装.

## SKILL.md 格式

`SKILL.md` 由 YAML frontmatter 和其后的 Markdown 正文组成. frontmatter 以单独一行 `---` 开始, 以单独一行 `---` 结束.

### frontmatter 字段

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `name` | 是 | NFKC 归一化后 1-64 字符; 只含 Unicode 小写字母和数字, 以及连字符 `-`; 不以连字符开头或结尾; 不含连续连字符; 与父目录名在 NFKC 归一化后相同. |
| `description` | 是 | 1-1024 字符; 非空; 说明做什么和何时使用. |
| `license` | 否 | 许可证名称, 或指向 skill 目录内许可证文件的引用. |
| `compatibility` | 否 | 1-500 字符; 说明运行环境要求, 如目标产品, 系统包, 网络访问. |
| `metadata` | 否 | 字符串键到字符串值的映射. |
| `allowed-tools` | 否 | 空格分隔的工具名字符串; 实验性字段, 支持程度因客户端而异. |

### name

+ 按官方 `skills-ref` 参考实现, 校验前先去除首尾空白并做 NFKC 归一化; 其后所有检查和长度计数都针对这个结果.
+ 去除首尾空白后必须满足本条下面的 Unicode 小写字母, 数字和连字符规则. 首尾空白只是被忽略, 不是放宽字符集: `name: " pdf-processing "` 归一化后为 `pdf-processing`, 合法; 但 `pdf processing` 去掉首尾空白后中间仍有空格, 仍属非法.
+ 长度 1-64 字符, 按归一化后的字符计数, 不按字节.
+ 只允许 Unicode 小写字母和数字, 以及连字符 `-`. 例如 `a-z`, `é`, `技能` 都合法; 采用兼容字符时以 NFKC 归一化后的结果判断.
+ 必须全部为小写, 不能含大写字母.
+ 不能以连字符开头或结尾.
+ 不能出现连续连字符.
+ 必须与父目录名在 NFKC 归一化后完全一致. 这样同一名称的 NFC 与 NFD 写法可以匹配同一目录. 父目录名只做 NFKC 归一化, 不执行 `name` 字段的去除首尾空白步骤, 因此目录名带首尾空白时视为不一致. 校验时使用解析后的实际目录名: 通过符号链接调用时, 比较目标是链接指向的目录名, 而不是链接名.

合法示例:

```yaml
name: pdf-processing
name: data-analysis
name: 技能
name: café
```

非法示例:

```yaml
name: PDF-Processing   # 含大写字母
name: -pdf             # 以连字符开头
name: pdf--processing  # 含连续连字符
name: pdf_processing   # 含下划线
name: 技能!            # 含非字母数字字符
```

### description

+ 长度 1-1024 字符, 不能为空.
+ 说明 skill 做什么, 以及何时使用.
+ 建议包含能帮助客户端识别相关任务的用户用语, 对象名, 动作和格式.
+ 描述会进入客户端的 skill 列表, 是激活前唯一的匹配依据.

合格示例:

```yaml
description: 从 PDF 提取文本和表格, 填写表单并合并文档. 在用户处理 PDF, 提到表单或要求文档抽取时使用.
```

不合格示例:

```yaml
description: 帮助处理 PDF.
```

不合格示例只有领域, 没有具体动作和触发语境.

### license

+ 可选.
+ 写许可证名称, 或指向 skill 目录内的许可证文件.
+ 标准没有规定长度和固定取值.
+ 建议保持简短.

示例:

```yaml
license: Apache-2.0
```

### compatibility

+ 可选.
+ 提供时长度 1-500 字符.
+ 说明目标产品, 需要的系统包, 网络访问或其他环境前提.
+ 大多数 skill 不需要此字段.

示例:

```yaml
compatibility: 需要 Python 3.9+ 和 git.
```

### metadata

+ 可选.
+ 必须是映射, 键和值都是字符串.
+ 标准允许客户端用此字段存放额外属性.
+ 键名建议保持唯一, 避免与其他 skill 或客户端冲突.
+ 未加引号的数字和布尔值会被 YAML 解析为非字符串, 必要时加引号.

示例:

```yaml
metadata:
  author: example-org
  version: "1.0"
```

### allowed-tools

+ 可选.
+ 必须是空格分隔的字符串, 不是列表.
+ 表示 skill 可以预先获准使用的工具.
+ 这是实验性字段, 不同客户端的支持程度不同; 不能假设所有客户端都会执行该声明.

示例:

```yaml
allowed-tools: Bash(git:*) Read
```

### 非标准字段

标准没有定义上述六个字段之外的 frontmatter 字段. 客户端可能忽略不认识的字段, 也可能自行解释. 因此:

+ 非标准字段不能作为 skill 正确运行的前提.
+ 依赖非标准字段时, 必须标注适用的客户端, 并提供不依赖该字段的替代做法.
+ `scripts/validate_skill.mjs` 把非标准字段列为警告, 严格模式下视为错误.

### 正文

+ frontmatter 之后是 Markdown 正文, 标准不限制正文格式.
+ 客户端激活 skill 时会加载完整正文.

## 渐进披露

标准建议按三层组织内容:

1. metadata: `name` 和 `description`, 启动时加载, 约 100 token.
2. instructions: `SKILL.md` 正文, 激活时加载, 建议少于 5000 token.
3. resources: `scripts/`, `references/` 和 `assets/` 中的文件, 按需加载.

`SKILL.md` 正文建议保持在 500 行以内. 超过时把细节移入参考文件或脚本.

## 文件引用

Agent Skills 规范推荐的写法是相对 skill 根目录的路径. `scripts/validate_skill.mjs` 的引用检查以此为主: 先按 skill 根目录解析, 找不到再按链接所在文件目录解析.

这个回退是校验器的兼容行为, 不是标准要求: 按标准写的 skill 应只使用相对 skill 根目录的路径, 换成其他客户端时才能解析到同一目标. 两种写法都能通过本 skill 的校验器, 但只能按所在文件目录解析的链接会得到警告, 提示改为相对 skill 根目录. 绝对路径链接 (`/...`) 的目标必须真实存在: 目标不存在按本地链接目标不存在报错, 目标存在时才给可移植性警告. 解析后落在 skill 目录外的链接同样能通过校验, 但会得到可移植性警告.

+ 在 `SKILL.md` 中引用时, 使用相对 skill 根目录的路径, 例如 `references/REFERENCE.md` 或 `scripts/extract.py`. `SKILL.md` 位于根目录, 相对所在文件和相对 skill 根目录在它上面指向同一位置.
+ 在 `references/` 内的文件互相链接时, 标准写法仍是相对 skill 根目录: 链接同目录的 `b.md` 写 `references/b.md`, 链接 `scripts/extract.py` 写 `scripts/extract.py`. 相对所在文件目录的写法 (`b.md`, `../scripts/extract.py`) 只有本 skill 的校验器接受, 换客户端可能失效, 并且会触发警告.
+ 不要使用以 `/` 开头的绝对路径链接, 不要使用 Windows 盘符 (如 `C:\work\demo.md`) 或 UNC 路径 (反斜杠形式如 `\\server\share\demo.md`, 正斜杠形式如 `//server/share/demo.md`), 也不要链接到 skill 目录外的文件: 它们在分发后无法解析到同一目标. 绝对路径链接的目标不存在时校验器直接报错 (按本地链接目标不存在处理), 目标存在时给可移植性警告; Windows 盘符或 UNC 路径一律给可移植性警告; 目录外链接给可移植性警告.
+ 同一个链接只按一种基准书写, 不要混用两种基准.
+ 从 `SKILL.md` 直接引用, 保持一层深度.
+ 避免参考文件再引用其他参考文件, 形成多层链.
+ 需要读取参考文件时, 在正文说明读取条件和用途.

示例 (`SKILL.md` 中的写法):

```markdown
需要完整字段表时读取 `references/spec.md`.
生成文件后运行 `scripts/validate_skill.mjs`.
```

## 资源目录职责

| 目录 | 放什么 | 加载或执行方式 | 约束 |
| --- | --- | --- | --- |
| `scripts/` | 确定, 可重复执行的代码 | 由执行者运行, 不进入上下文 | 自包含或明确声明依赖; 错误信息可操作; 处理边界情况 |
| `references/` | 按分支读取的文档, 规范, 模板说明 | 需要时读取 | 单个文件保持聚焦; 文件越小, 按需加载越省上下文 |
| `assets/` | 进入产物的静态资源 | 通常由脚本读取, 不直接进入上下文 | 模板, 图片, 数据文件; 路径由脚本或正文明确引用 |

脚本语言没有标准限制. 常见选择是 Python, Bash 和 JavaScript, 实际支持取决于客户端.

## 标准字段与厂商扩展

### 可移植的标准内容

+ frontmatter 的六个标准字段.
+ 目录名与 `name` 一致.
+ `SKILL.md` 加 `scripts/`, `references/`, `assets/` 的目录约定.
+ 相对 skill 根目录的一层文件引用.
+ Markdown 正文中的步骤和说明.

只依赖这些内容时, skill 可以在不同客户端之间迁移.

### 常见厂商扩展

下表只说明差异, 不构成推荐用法. 具体客户端行为以目标客户端当前文档为准 (下表信息截至 2026-10).

| 来源 | 机制 | 其他客户端的行为 |
| --- | --- | --- |
| Claude Code | 额外 frontmatter, 如 `disable-model-invocation`, `user-invocable`, `argument-hint`, `context`, `agent`, `hooks`, `model`, `disallowed-tools`, `shell` | 本地加载通常忽略不认识的字段, 因此不会得到相同的调用控制或执行行为; 但 claude.ai 上传, Skills API 和 `package_skill.py` 会拒绝标准外字段并报 `Unexpected key(s)`, 不能假设所有路径都忽略 |
| Claude Code | `${CLAUDE_SKILL_DIR}` 等变量替换, `` !`command` `` 动态上下文注入 | 不会替换或执行, 文本可能原样出现 |
| Codex 与 ChatGPT | 可选的 `agents/openai.yaml`, 包含界面元数据, 调用策略和工具依赖 | 忽略该文件, 界面和调用策略不生效 |
| Claude Code, Codex, Vercel | plugin 或插件目录, marketplace manifest | 安装和分发方式不同, 不属于 Agent Skills 标准 |
| 各客户端 | `allowed-tools` 的具体语法和权限语义 | 字段属于标准, 但支持程度和解释不同, 不能依赖统一的权限行为 |

使用厂商扩展时:

+ 核心流程必须只依赖标准内容.
+ 在正文中标注扩展适用的客户端.
+ 提供不使用该扩展时的替代步骤.
+ 不把厂商的工具名, 元数据文件或调用方式写成通用规则.
+ 不把"忽略"当作唯一行为: 部分上传或打包路径会直接拒绝未知字段, 使用前按目标分发路径验证.

## 校验脚本覆盖的检查

`## 前提条件` 一节的存在性与条目内容不在 `scripts/validate_skill.mjs` 的自动检查范围内, 必须人工核对; 该节是本流程的强制项, 不是 Agent Skills 标准的要求, 因此脚本输出 `校验通过.` 只表示标准约束通过, 不代表该节已满足.

`scripts/validate_skill.mjs` 把标准的明确违规作为错误:

+ frontmatter 缺失或不可解析.
+ `name` 缺失, 不是字符串, 长度或字符集不合法, 或与目录名不一致.
+ `description` 缺失, 不是字符串, 为空或超长.
+ `license`, `compatibility`, `metadata`, `allowed-tools` 的类型, 长度或空格分隔格式不合法. `allowed-tools` 是空格分隔的字符串, 含逗号, 分号或空格以外的空白字符 (如制表符) 即报错.
+ 正文为空.
+ `SKILL.md` 或 `references/` 下的 Markdown 参考文件 (`*.md`) 中的本地链接目标不存在, 包括以 `/` 开头的绝对路径链接指向不存在的目标. 本地链接先按 skill 根目录解析, 未找到再按链接所在文件目录解析. 解析路径前先对目标做 HTML 实体解码和百分号解码: 命名 HTML 实体按完整实体表解码 (`decode-named-character-reference`), 例如 `&sol;` 按 `/` 处理, `&amp;` 按 `&` 处理; 数字实体按码点解码, 无效码点 (NUL, 代理区 U+D800-U+DFFF, 超出 U+10FFFF) 按 U+FFFD 替换, 与 Python `html.unescape` 一致. 与 Python `html.unescape` 一致, legacy 命名实体 (如 `&amp`, `&lt`, `&gt`, `&quot`, `&nbsp`, `&copy`, `&reg` 等) 与数字实体 (如 `&#65`, `&#x41`) 允许省略结尾分号: 命名实体先按完整名称查找, 未命中时取最长的 legacy 名称前缀, 其余字符原样保留, 因此 `&ampb` 按 `&b` 处理, `&#65b` 按 `Ab` 处理; 非 legacy 名称省略分号时不解码 (如 `&hellip` 保留原文), 未知实体保留原文. `%20` 按空格处理, `%25` 按 `%` 处理, 其他百分号转义同理. 因此文件名含空格时链接写 `%20`, 含 `%` 时写 `%25`. 链接检查使用 CommonMark 解析: 覆盖 Markdown 链接与行内 HTML 属性, 跳过外部链接, 纯锚点, 行内代码, 围栏代码块, 缩进代码块, HTML 注释和原始 HTML 块中的内容; 原始 HTML 块内的链接不检查, 块外的链接照常检查. 同一行内指向同一目标的多条链接按 "行号 + 解码后的完整目标 (含片段与查询)" 去重, 只报告一次, 不同行或不同目标分别报告; 同一路径但片段或查询不同时分别报告. 链接标签回溯不设固定长度上限, 以空行或文本开头为终止. 行内 `<a href>` 与 `<img src>` 目标也按本地链接检查. 行内标签可以跨行 (只要 CommonMark 仍把整段识别为行内 HTML), 属性可以写在标签内的任意一行, 目标缺失按属性值所在行报告行号; 标签从标签名之后到 `>` 的总长有上限 (2048 字符), 超限时按普通文本处理, 避免未闭合的 `<a` 吞掉后文. 属性值内的换行按 HTML 规则处理: 引号内的换行属于属性值, 未加引号的值在换行等空白处结束. 反斜杠转义的 HTML 标签 (如 `\<a href="x">`) 在 CommonMark 中是字面文本, 不是标签, 因此不按链接检查. CommonMark 自动链接 (如 `<https://example.com>`) 与片段锚点 (`#...`) 不自动检查, 需要人工核对: 脚本不判断外部 URL 是否可达, 也不校对标题锚点是否存在. 纯锚点只跳过存在性检查, 其中的控制字符仍按下面的规则检查. 脚注标签 (`[^1]: ...`) 不按引用定义处理. 参考文件链接扫描只覆盖 `references/` 下不在隐藏文件或依赖目录中的 `.md` 文件; `references/` 下的其他文本文件 (如 `references/a.txt`) 中的链接不自动检查, 需要人工核对.
+ 本地链接目标包含 NUL 或 Unicode Cc 类控制字符 (含 C0, DEL 与 C1). 检查对象是完整链接目标, 含 `#` 后的片段与 `?` 后的查询, 不因按路径解析而截断, 因此片段或查询中的控制字符同样报错; HTML 实体与百分号编码按与路径解析相同的顺序解码后再判断. 纯锚点与仅含查询的目标也检查, 不因跳过存在性检查而豁免; 外部链接仍不做控制字符检查: 带 scheme 的目标 (如 `http:`, `https:`) 与不构成 Windows UNC 路径的 `//` 开头目标都属外部链接; 正斜杠 UNC 形式 (`//host/share/...`) 不是外部链接, 与 Windows 盘符路径一样检查控制字符, 并按不可移植路径给出警告. 这类目标不进入文件系统调用, 直接报错并给出转义后的目标. 行内链接目标, 行内 HTML 属性目标与引用式定义目标 (`[标签]: 目标`) 都检查: 定义目标即使因控制字符未被 CommonMark 解析, 也按定义起始行起的原始文本扫描并报同样的错误, 该标签仍视为已定义, 因此引用它时不再报定义缺失; 脚注定义 (`[^1]: 目标`) 不是链接, 不检查. 原始文本扫描只把 `]` 前存在未转义 `[` 或 `![` 的目标视为行内链接, 普通文本中的闭括号后紧跟圆括号不算链接, 不检查. CommonMark 允许目标另起一行: 行内链接可在开括号 `(` 后换行一次, 引用式定义可在冒号后换行一次, 续行缩进可包含任意空格与制表符; 只允许一个换行, 目标本身仍须在同一行内写完. 这类跨行目标的控制字符错误按链接或定义的起始行报告, 不按目标所在的续行. 该回退只适用于目标行其余部分为空或只有合法标题; 目标后出现其他文本时该行不构成定义, 按定义不存在报错.
+ 引用式链接定义不存在. 正文中 `[文本][标签]` 形式的引用式链接没有对应的 `[标签]: 目标` 定义时报错. 定义存在时其目标按上面的本地链接规则检查, 不重复报错. 与链接检查使用同一套屏蔽文本, 代码块和原始 HTML 块内的 `[文本][标签]` 不计; 空标签的折叠引用 (`[文本][]`) 和快捷引用 (`[标签]`) 不做存在性检查, 需要人工核对. 定义标签内允许反斜杠转义 (如 `[a\]b]: 目标`), 只有未转义的 `]` 才闭合标签. 定义可以写在同一行, 也可以把目标写在下一行; 列表项和块引用内的定义按 CommonMark 规则识别. 目标后可跟可选标题 (`"标题"`, `'标题'` 或 `(标题)`), 标题可以与目标同行或独占紧随的一行, 也可以在后续行闭合. 缺失定义只在 AST 未解析为链接的文本中扫描, 因此与 CommonMark 解析结果一致. 仍有三类写法不登记定义, 引用方会报 `引用式链接定义不存在`, 属于错误而不是警告, 人工核对无法消除, 需要改写: 紧跟普通正文行或列表项行的 `[标签]: 目标` (如 `Some text` 换行 `[标签]: real.md`) 是段落的惰性续行, 定义不能打断段落, 应把定义顶格放在块首, 即与上一段之间空一行, 或把它移到文档或章节开头. 列表项内容中相对列表项内容缩进 4 个空格的 `[文档]: 目标` 属于缩进代码, 应写成同行的 `- [文档]: 目标`, 或把定义移到列表之外顶格书写. `[标签]:` 之后紧跟 `---`, `===`, `==` 或 `# 标题` 这类块级标记时, 该行按 Setext 标题下划线, 分隔线或 ATX 标题处理, 不构成定义, 应把目标与标题写在同一行 (如 `[标签]: 目标 "标题"`), 不要依赖跨行的块级标记.

脚本把可移植性和冗余问题作为警告:

+ 非标准 frontmatter 字段.
+ `scripts/` 或 `references/` 中未被 `SKILL.md` 直接引用或正文提到的文件. 只有 `SKILL.md` 自身的 Markdown 链接, 行内 HTML 链接和正文纯文本提及能豁免; 参考文件之间的链接 (含行内 HTML 链接) 不算, 只用于互引和链接存在性检查. 顶层文件, `assets/`, 隐藏文件, 依赖目录, `__pycache__` 目录与 `.pyc` 文件不检查: `assets/` 资源可能由脚本在运行时拼接路径, 顶层文件如 `LICENSE` 属于随 skill 分发的材料, 不是激活时加载的上下文, 依赖目录由安装命令生成, 不是源文件, `__pycache__` 与 `.pyc` 是本地 Python 解释器生成的字节码缓存, 也不是源文件. 依赖目录指路径中任一分量属于固定集合 `node_modules`, `vendor`, `third_party`, `venv`, `virtualenv`, `site-packages` 时跳过, 该集合是本校验器的约定, 不是 Agent Skills 标准要求; 集合之外的目录 (如 `references/custom/`) 仍按未引用文件检查.
+ 例外: frontmatter `license` 的值整体指向 skill 目录内的现有文件时, 该文件视为已引用. 普通许可证名称(如 `MIT`, `Apache-2.0`)不受影响.
+ 参考文件互相引用.
+ 绝对路径链接 (`/...`, 不含 `//` 开头的目标: 构成 UNC 的按下面的 Windows 路径处理, 其余按外部链接跳过), 仅在目标存在时给出: 不可移植. 目标不存在时按上面的链接错误处理.
+ Windows 盘符路径 (如 `C:\work\demo.md`) 或 UNC 路径 (反斜杠形式如 `\\server\share\demo.md`, 正斜杠形式如 `//server/share/demo.md`): 不可移植. 这类路径在其它平台上无法解析, 一律给警告, 不做目标存在性检查. 正斜杠 UNC 形式 (`//host/share/...`) 按 Windows UNC 路径处理, 不是外部链接; 带协议的外部链接 (如 `http://example.com/a.md`, `https://example.com/a.md`) 仍按外部链接跳过.
+ 解析后落在 skill 目录外的链接: 不可移植.
+ 链接路径大小写与磁盘不一致: 精确路径不存在, 但按大小写折叠能找到磁盘上的同名路径时, 按可移植性警告处理, 该目标仍视为已引用. 上述结论在 POSIX 文件系统上成立: 同一份文档在大小写敏感与不敏感文件系统上得到一致的结论. 在大小写不敏感的文件系统上, 解析可能先返回磁盘的规范大小写, 该警告可能不触发, 需要在目标平台人工核对; 路径分量大小写不一致在分发后可能失效.
+ 参考文件中只能按所在文件目录解析的链接: 建议改为相对 skill 根目录. 两种基准都能解析时不给该警告; `SKILL.md` 内的链接不触发该警告.
+ 正文超过 500 行.

对参考文件互引, 脚本检查 Markdown 链接与行内 HTML 链接形式; 正文中的纯文本提及不会触发警告, 需要人工核对.

frontmatter 使用 `yaml` 包按 YAML 1.2 core schema 解析, 支持该库接受的完整 YAML 语法. 与 PyYAML 的 YAML 1.1 行为不同:

+ `yes`, `no`, `on`, `off` 按字符串处理, 不再转换为布尔值; 形如日期的纯量按字符串处理, 不再转换为日期; 六十进制整数和浮点数不再识别. 这些差异只影响字段类型判断, 不是解析错误.
+ 重复键按解析错误处理: 同一映射中键重复时 frontmatter 视为不可解析, 校验失败并以状态 1 退出. PyYAML 接受重复键并让后者覆盖前者, 不报错也不警告, 因此同一份 frontmatter 在 YAML 1.1 下能通过, 在本校验器中会报错.
+ `<<` 合并键不再展开: YAML 1.2 core schema 不包含合并键, `<<` 按普通映射键处理, 其值不会被合并进所在映射. 因此 `metadata: {<<: *defaults}` 里的 `<<` 是值为映射的普通键, 本校验器报 `metadata.<< 的值必须是字符串` 并以状态 1 退出; PyYAML 按 YAML 1.1 展开合并, 同一份 frontmatter 在 1.1 下能通过. 需要共享或复用字段时显式写出每个键值, 不要使用 `<<`.
+ 解析错误文案来自 `yaml` 库, 与 PyYAML 不同. 例如重复键报 `无法解析 frontmatter: Map keys must be unique`, 错误前缀和行号由本校验器补充, 冒号后的具体原因由库给出.

这是相对 YAML 1.1 的行为变化, 按新语义编写 frontmatter: 每个映射的键保持唯一, 不要依赖重复键的覆盖顺序; 不要使用 `<<` 合并键, 需要复用字段时显式写出; 也按 YAML 1.2 core schema 理解纯量类型. 使用 `--verbose` 时输出 `frontmatter 解析器: yaml <版本>`.

默认情况下警告不影响退出状态; `--strict` 把警告升级为错误.
