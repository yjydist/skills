# 论文第一遍阅读 (Paper First Pass)

帮助读者第一次读懂一篇学术论文, 并决定是否继续投入时间. 默认读者有日常理解能力, 但没有相关领域知识, 也不假定有计算机本科基础. 成功标准是读者能用自己的话说明: 谁遇到了什么问题, 作者怎么解决, 有什么依据, 还有什么限制.

## 前提条件

+ 运行时: 无. 检查: `true`; 以状态 0 退出表示本项没有需要检测的运行时.
+ 第三方依赖: 无. 检查: `true`; 以状态 0 退出表示本项没有需要安装或导入的包.
+ 外部程序与认证: 无. 检查: `true`; 以状态 0 退出表示本项没有需要检测的外部程序或认证. 读取 PDF 与获取链接内容的能力由执行工具提供, 不要求特定程序.
+ 检查命令按 POSIX shell (sh/bash) 编写. 以 `true` 作为检查命令的条目表示该项无要求, 在不支持 `true` 的 shell 中直接视为通过.

## 核心原则

+ 第一遍只抓主线, 但主线必须讲明白. 不以章节齐全, 篇幅短或术语多作为理解到位的标志.
+ 作者的主张, 论文提供的证据与自己的判断分开表述. 用"作者认为", "作者报告", "根据已读内容, 我的判断是"等措辞说明归属; 实验结果不自动构成普遍结论.
+ 关于论文的事实和结论只依据实际读取的内容. 为帮助理解补充的日常场景或类比需明确标注, 不冒充论文案例, 实验或结论.
+ 用户已说明知识背景时据此调整解释深度; 未说明时直接按无领域基础讲解, 不要求先补完基础课程.

## 面向新读者的讲解规则

+ 先给具体场景, 再引入概念. 说明谁想做什么, 遇到什么困难, 原来的办法为什么不够好. 原文有合适案例时优先使用; 自拟场景用"举个便于理解的假设例子"等措辞标明.
+ 用动作和因果串起方法: 谁拿到什么, 做了什么, 得到什么, 这一步为什么可能缓解前面的困难. 理论或综述论文则说明要回答的疑问和推理或整理思路, 不硬套系统的输入输出.
+ 只引入理解主线必需的术语. 先用日常语言说明意思及其在本文中的作用, 再给名称; 为便于回查原文才保留英文或缩写. 不用另一个未解释的术语下定义, 不把解释全部推到文末词汇表.
+ 区分通用概念解释与本文的具体实现. 即使只有摘要, 也可以补充理解主线所需且能够可靠说明的一般背景, 标明这是帮助理解的概念说明; 不能由此推断本文采用了某种具体流程或已经满足某项保证. 不因原文缺少实现细节就省略必要的基础解释, 不影响主线的术语则直接省去.
+ 抽象机制优先尝试贴切的生活类比, 交代类比中的对象和动作分别对应论文中的什么, 然后回到实际方法. 类比会在关键条件上误导时说明不相同的地方; 找不到贴切类比时改用具体例子或分步解释, 不强凑. 类比帮助理解, 不作为方法有效或安全的证据.
+ 使用自然, 连贯的段落, 一步一步补齐理解所需的信息, 不把回答压缩成术语提纲. 不设强制句数或篇幅上限; 解释清楚后停止, 不重复扩写, 不展开与主线无关的基础课程.
+ 多方交互或流程仅靠文字不容易分清时, 可用简单 Mermaid 图辅助. 图中的角色和动作仍需用正文说明, 不以图代替讲解.

## 工作流程

### 1. 获取论文内容

接受用户提供的 PDF, arXiv 页面, 论文全文文本或其他可读取的论文格式.

+ 确认读取到的是学术论文或可识别的论文片段. 博客, 新闻或课程笔记等非论文输入应说明不适用并停止; 综述, 评测, 数据集及理论论文仍可处理, 按实际类型解释贡献证据.
+ PDF 内容解析失败时, 明确向用户指出失败并停止, 不根据标题或常识猜测论文内容继续输出报告.
+ 用户提供的是链接时, 先获取实际内容再进入阅读; 获取失败时如实报告, 不凭记忆补全.
+ 只有摘要或部分章节时, 在报告开头标明实际读取范围和判断限制, 仅解释材料支持的内容. 某一部分没有足够信息时在对应位置直说缺少什么, 不为填满模板补造方法, 实验, 证明或全文结论.

### 2. 按优先级阅读

按以下顺序优先阅读:

1. 标题与摘要.
2. 引言与作者列出的贡献.
3. 展示方法全貌, 系统结构或处理流程的主要图示.
4. 主要实验表格和结果图; 非实验型论文则读主要命题, 成立条件或综述的组织方式.
5. 结论, 讨论与限制.
6. 必要时浏览章节标题, 补读理解核心机制或关键条件所需的段落.

不要只因摘要出现了某种技术名称, 就自认为已经理解方法. 主线存在缺口时回到原文补读; 仍无法确认的地方如实保留. 第一遍不展开数学推导, 完整证明, 算法实现, 全部附录或实验配置审计.

### 3. 串起四个问题

先在同一个场景或研究问题中理清以下关系, 再组织报告. 无法回答的部分标明缺口:

1. **问题**: 具体困难是什么, 谁会关心, 以前怎么处理, 作者认为哪里不够好?
2. **方法**: 作者改变了什么, 为什么这个变化可能解决困难? 贡献是新思路, 实现, 数据, 评测方式, 理论结果还是实证发现?
3. **证据**: 作者实际做了什么实验, 论证或整理工作, 观察到了什么, 支持了多大范围的结论?
4. **边界**: 方法或结论依赖哪些条件, 付出什么代价, 什么尚未解决, 什么只是当前没有读到或核实?

### 4. 生成报告

生成前读取 [报告模板](references/report-format.md), 按"直观概览, 问题, 方法, 证据, 边界, 接下来怎么读"输出 `# 论文第一遍阅读 (Paper Snapshot)` 报告. 模板规定各部分的内容和证据写法, 不要求每部分压缩成几句话.

+ 将重要图表放在对应的讲解中, 说明应该看哪里, 读到了什么, 为什么与当前问题有关.
+ 关键判断就近附实际读取到的章节, 页码, 图表或命题定位, 无法定位时说明. 不伪造编号, 不把摘要中的主张当作已检查过的全文证据.
+ 用户提供研究目标时, 在后续阅读建议中直接结合目标判断; 未提供时按不同用途给条件性建议, 不猜测其专业, 项目或毕设方向.

### 5. 检查读者能否复述

+ 逐段检查关键概念是否已经解释, 解释是否又引入了陌生概念, 方法到效果之间是否缺少原因. 有缺口时先补解释, 不是仅替换成中文术语.
+ 检查是否只剩"提高安全性", "提升性能", "采用先进技术"等说法. 改为具体说明保护了谁的什么信息, 减少了哪一步的时间或错误, 或改变了哪种条件下的结果.
+ 检查类比能否对应实际机制, 是否暗中增加了可信第三方, 免费计算或其他原文没有的条件. 会误导就修正, 限定或移除.
+ 检查读者能否沿着场景说清问题, 做法, 依据与限制. 为此需要的背景应在正文中补足; 只有深入推导或实现才需要的知识留到后续阅读建议.

## 操作边界

+ 不逐段摘要, 不罗列论文中出现的全部术语, 不将第一遍变成完整证明, 实现教程或实验审计.
+ 不为凑限制而挑毛病, 只记录原文明示或当前证据可以支持的问题. 没有读到证据, 不等于方法已经被证明无效.
