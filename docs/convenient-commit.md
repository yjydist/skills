# convenient-commit 使用文档

`convenient-commit` 用于规划 Git 提交边界, 拟定和检查提交消息, 或将授权范围内的改动拆分为完整的本地提交. 它按行为和意图分组, 不按文件数或改动行数机械拆分.

## 使用前提

+ 将 [skill 目录](../skills/convenient-commit/SKILL.md) 连同 `references/` 中的参考文件一起提供给支持 skill 的工具.
+ 让执行工具能够访问目标 Git 仓库, 并读取相关差异和仓库规范. 实际提交还需要相应的本地写入权限及仓库要求的验证环境.
+ 在请求中说明处理范围和期望结果. 已有未提交或已暂存内容不会自动成为提交授权范围.

下方示例使用 `$convenient-commit` 表示调用该 skill. 如果所用工具不支持这种调用形式, 可以直接指定 `skills/convenient-commit/SKILL.md` 的实际路径, 要求按其中的指导处理目标仓库.

## 调用示例

### 仅规划拆分

```text
使用 $convenient-commit 检查当前仓库的未提交改动, 给出提交拆分方案.
说明每条提交的拟定标题, 主要范围, 分组理由, 依赖顺序和验证建议.
本次只规划, 不修改文件, 不暂存, 不创建提交.
```

预期结果是可审查的提交方案. 一个完整目的可以跨越多个文件, 修复及其回归测试通常放在同一条提交. 若全部差异只表达一个目的, 保留一条提交即可.

### 仅拟定消息

```text
使用 $convenient-commit 为当前暂存区的改动拟定提交消息.
遵循仓库已有的消息约定, 仅输出草案, 不改变暂存区或创建提交.
```

预期结果是基于暂存差异的标题, 以及确有必要的正文或尾注. 消息语言和格式优先遵循用户要求, 其次是仓库规范和一致的历史惯例; 都没有时默认使用中文 Conventional Commits. 草案不会把未执行的验证写成已经通过.

### 拆分并提交

```text
使用 $convenient-commit 将当前仓库中与登录过期处理有关的改动拆分并提交.
包括实现, 调用点, 对应测试和必要文档, 其他改动保持原状.
每条提交验证通过后创建本地提交, 完成后报告提交记录和剩余改动.
```

预期结果是按依赖顺序创建的本地提交, 每条包含一个完整目的. 执行工具会简述分组, 精确暂存并验证待提交快照, 完成后报告实际短哈希, 标题, 目的和验证结果. 授权明确时不会为每条常规提交重复请求确认.

## 已有暂存内容和异常处理

+ 普通 `git commit` 会包含全部暂存内容. 如果其中有超出本次授权的改动, 必须安全隔离并保留原内容和暂存选择; 无法安全隔离时会说明具体阻塞, 不擅自清空暂存区或一并提交.
+ 工作区中还保留后续提交的代码时, 仅运行整个工作区的测试不足以证明当前提交成立. 验证必须对应每条待提交快照.
+ 验证无法运行或失败时, 会说明未验证项, 原因及已有问题的对比证据. 不把缺失验证当作通过, 未授权带风险提交时不继续提交.
+ 钩子修改文件或拒绝提交时, 会重新核对差异和验证结果. 只处理当前授权范围内的修正, 不绕过钩子, 不把失败尝试报告为成功.
+ 没有待提交改动时直接说明, 不创建空提交. 仅提供方案或消息草案时不会输出虚构的提交哈希.

提交授权仅涵盖新的本地提交. 推送, 修改已有提交或重写历史需要另外的明确授权; skill 不会擅自丢弃改动或改变 Git 身份, 签名及钩子配置.
