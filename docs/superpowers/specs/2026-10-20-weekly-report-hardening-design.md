# weekly-report 修正与加固设计

日期: 2026-10-20
状态: 待评审

## 目标

修正 `weekly-report` skill 中已复现的渲染缺陷, 收紧输入校验, 并消除模板重复与多页报告无法辨识归属的问题. 交付物仍为 A4 尺寸 300 DPI PNG 与可独立编译的 Typst 源文件; 报告内容仍完全来自用户, 不代写, 不改写, 不缩字控页.

## 背景与实测结论

审查时以 Typst 0.15.1 真实渲染验证, 基础测试 15 项与真实渲染测试均通过. 以下问题均为实测复现, 而非推测.

+ 长英文串溢出. 160 字符的 URL 会冲破内容列, 压过备注列并延伸到表格外, Typst 本身不报错. 实测 `#set par(linebreaks: "optimized")` 与 `hyphenate: true` 对连续拉丁串均无效.
+ 条目内空白被折叠. 前导缩进与连续空格在渲染时合并为单个空格, 与 `SKILL.md` 中"原样保留"的表述不符. 已决定不改渲染行为, 只修正文档表述.
+ 冲突提示写死"周报". 渲染月报时同样输出"已有同名周报产物".
+ 非法 JSON 报英文原文. `main()` 直接把 `json.JSONDecodeError` 文本抛给用户, 与其余中文错误口径不一致.
+ 字体警告噪音. 模板字体列表首项 `Alimama FangYuanTi VF` 缺失时, 每次渲染都输出 `warning: unknown font family`, 而 `font_note` 为 `null`.
+ 输入校验缺口. `start`/`end` 不校验格式与月份一致性; 考勤字段接受任意非空字符串; 数字使用 `format(value, "g")`, 大整数会变成 `1.23457e+06`.
+ 模板重复. 两个模板共 171 行, 仅 6 处差异, 版式改动需要改两遍.
+ 多页归属缺失. 第 2 页起只重复表头, 没有姓名与日期, 打印装订后脱离首页无法辨识.

## 方案

### 1. 渲染管线与模板结构

新增 `skills/weekly-report/references/layout.typ`, 只包含版式与结构, 不包含数据:

+ 页面尺寸与页边距, 字号, 语言与地区.
+ 长串断行规则.
+ 单元格辅助函数 `head-cell`, `cat-cell`, `body-cell`.
+ 大标题, 信息行, 表格结构, 五个类别行.

`layout.typ` 引用 `report`, `period`, `title` 三个由模板定义的变量.

两个模板各自只保留三部分:

+ 数据块, 仍用 `// REPORT_DATA_START` 与 `// REPORT_DATA_END` 标记; 模板内保留完整示例数据, 以便阅读.
+ `#let period = "本周"` 或 `#let period = "本月"`.
+ `#let title`, 周报为 `[#(report.year)年#(report.month)月第#(report.nth)次周报]`, 月报为 `[#(report.year)年#(report.month)月月报]`.

模板中不出现任何按 `kind` 分支的条件逻辑, 保持 `31f431e` 的拆分意图.

渲染脚本 `build_source()` 的组装顺序:

1. 数据块 (由报告数据替换标记之间的内容).
2. `#let period = ...` 与 `#let title = ...` 由模板原样保留.
3. 由脚本注入的字体设置行, 见第 5 节.
4. `layout.typ` 全文.

产物 `.typ` 因此自包含, 可独立编译, 不依赖临时 JSON 或 skill 安装路径. 代价是单独打开 `weekly-template.typ` 无法编译, 这一点在模板文件头注释与使用文档中写明.

### 2. 长串断行

`layout.typ` 增加一条 `show regex` 规则, 匹配连续 16 个以上属于 `[A-Za-z0-9/:._?=&%~-]` 的字符, 每 12 个字符插入一次 `U+200B` 零宽空格.

实测结果: URL, Windows 路径, commit hash 均能在列内正常折行; 中英混排中的长 token 同样生效; 普通短词换行行为不变. 短条目不会触发, 因为匹配要求至少 16 个字符.

该规则作用于所有渲染出的字符串单元格, 包括长短条目.

### 3. 多页信息行

去掉表格上方独立的无边框信息表, 把信息行改为表格 `table.header` 的第一个元素:

+ 一个 `colspan: 3` 的单元格, `stroke: none`.
+ 内边距为顶部与左右 0, 底部 8pt, 保持与原版接近的垂直间距.
+ 单元格内含一个按 17.6% / 39.7% / 42.7% 分列的 grid, 依次放姓名, 学号, 日期.

效果: 首页外观与原版基本一致, 第 2 页起信息行与表头一起重复.

已知差异: 受表格内边距影响, 信息行左右位置与旧的独立表有约 1 至 2pt 偏差. 该差异在交付前的人工看图环节确认可接受.

### 4. 输入契约与严格校验

字段集合不变, 新增以下校验:

+ `start` 与 `end` 必须匹配 `YYYY.M.D` 且为真实存在的日期, 使用 `datetime.date` 校验排除 `2026.2.30` 一类输入; 要求 `start <= end`.
+ 周报: `start` 的年月必须等于 `year` 与 `month`; `end` 可在同月或次月, 以容纳跨月的一周.
+ 月报: `start` 与 `end` 均必须在 `year` 与 `month` 内.
+ `attendance_hours` 与 `attendance_early` 只接受数字 (整数或浮点), 字符串一律报错, 并在错误信息中说明应传数字. 布尔值不算数字.
+ `attendance_hours` 取值区间为大于 0 且不超过 24; `attendance_early` 必须为非负整数, 月报上限 31, 周报上限 7.
+ 数字格式化不再使用 `format(value, "g")`: 整数值输出为整数, 浮点去掉多余的末尾 0, 避免科学计数法.

日期与考勤的每条错误信息都包含期望格式, 便于用户直接修正.

输入契约以 `SKILL.md` 中的 JSON 示例为唯一准绳, 新增测试从该文件解析示例, 断言其键集合与 `REQUIRED` 完全一致, 且示例值与类型能通过 `validate_report()`. 不新增 CLI 子命令.

### 5. 错误信息与字体处理

+ 冲突提示按 `kind` 取词: 周报输出"已有同名周报产物", 月报输出"已有同名月报产物". `check_conflicts()` 因此需要接收 `kind` 或完整的 stem 描述.
+ 非法 JSON 转为中文 `ReportError`, 消息包含行列位置, 不再透出英文 `Expecting value`.
+ `check_environment()` 除可执行文件与提示外, 额外返回实际可用的字体族: 优先 `Alimama FangYuanTi VF`, 其次 `Alimama FangYuanTi`, 两者都不存在时为 `None`.
+ 有可用字体族时, 脚本只注入该族, 不再注入整个列表, 从而消除每次渲染的 `unknown font family` 警告.
+ 无可用字体族时不注入字体设置, 由 Typst 使用默认字体, `font_note` 与 stderr 提示保持现有行为.

## 不在本次范围

+ 不合并两个模板为单文件, 不使用按 `kind` 分支的条件逻辑.
+ 不提供 PDF 输出.
+ 不改页面尺寸, 字号, 页边距, 表格列宽.
+ 不改变"内容一律来自用户, 不润色"的边界.

## 风险与取舍

+ 严格校验会让历史上能通过的输入报错, 例如 `2026-03-02` 或带单位的考勤字符串. 每条错误信息都会给出期望格式.
+ 共享 `layout.typ` 后, 模板文件不能单独编译. 这换取版式只维护一处, 并在文档中明确说明.
+ 零宽空格会进入 PNG 的排版结果. 用户从图片复制文字时会带上不可见字符, 但不影响视觉内容. 若后续不能接受, 可改为脚本侧预处理, 代价是产物 `.typ` 中的文本与用户原文不再逐字相同.

## 验收标准

+ 基础测试与真实渲染测试全部通过.
+ 含 160 字符 URL 的条目不再溢出表格, 且不改变其他条目的换行.
+ 多页报告第 2 页起同时出现表头与姓名, 学号, 日期.
+ 渲染月报遇到同名产物时提示"月报".
+ 非法 JSON 与非法日期均输出中文错误并给出期望格式.
+ 已安装目标字体时, 渲染过程不再出现 `unknown font family` 警告, 且 `font_note` 为 `null`.
+ `SKILL.md`, `docs/weekly-report.md`, 模板与脚本对输入契约与产物行为的描述一致.
