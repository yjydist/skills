# paper-first-pass 使用文档

`paper-first-pass` 帮助读者第一次读懂一篇论文, 并决定是否继续阅读. 默认读者具备日常理解能力, 但没有相关领域知识, 不需要有计算机本科基础. 报告以图为主, 短文补充, 用具体场景和贴切类比讲清概览, 问题, 方法与贡献, 不要求读者先查一串术语才能跟上.

第一遍抓住主线, 不展开完整证明, 算法实现或实验审计. 讲解可以补足必要背景, 不以句数或篇幅上限强行压缩; 是否读懂, 看读者能否用自己的话说明论文做了什么, 为什么可能有用, 有什么依据和限制.

## 使用前提

+ 将 [skill 目录](../skills/paper-first-pass/SKILL.md) 连同 [报告模板](../skills/paper-first-pass/references/report-format.md) 一起提供给支持 skill 的工具, 保持两者的相对路径.
+ 本 skill 无固定运行时, 第三方依赖, 外部程序或认证要求. 这三类前提各用 POSIX shell 命令 `true` 检查, 状态 0 表示无须准备相应依赖; 不支持 `true` 的 shell 可直接视为通过.
+ 读取 PDF 与获取链接内容的能力由执行工具提供, 不要求特定程序. 执行工具仍须实际读到用户提供的论文或论文片段, 不能凭标题或记忆生成报告.
+ 图示的展示能力由执行工具提供. Mermaid 和 SVG 可直接编写, 无须准备固定绘图库或渲染程序. 当前环境无法展示所选格式时改用可展示的格式; 都不可用时说明限制并提供简短文字替代, 不强制安装工具.
+ 可以只提供摘要或部分章节, 此时报告会明确读取范围和判断限制; 对未读内容不补造结论. 不需要先提供研究方向或知识背景; 提供后会据此调整解释和相关判断.

下方示例使用 `$paper-first-pass` 表示调用该 skill. 如果所用工具不支持这种调用形式, 可以直接指定 `skills/paper-first-pass/SKILL.md` 的实际路径, 要求按其中的指导处理.

## 报告长什么样

报告标题为 `# 论文第一遍阅读 (Paper Snapshot)`, 开头列出论文信息, 来源与实际阅读范围, 然后按以下顺序展开:

1. **概览:** 用大白话说明论文研究什么, 怎么解决, 有什么主要进展.
2. **问题:** 从具体场景或研究疑问说明需求, 原来的办法和不足.
3. **方法:** 沿用前面的场景, 解释作者做了什么, 步骤怎样衔接, 为什么可能有用.
4. **贡献:** 对比原有工作说明改变和进步, 并结合实际读到的实验, 论证或其他依据说明条件和限制.

证据与边界放在相关讲解中, 不单列主要章节. 默认不提供后续阅读建议; 用户明确要求时才结合用途简短说明, 只指向已确认的阅读位置.

能用简洁图示讲清的流程, 结构和对比, 优先用图替代大段文字, 不先给完整长文再附一张重复内容的图. 正文保留必要背景, 读图提示, 为什么可能有效及适用条件, 不逐节点复述. 不规定每节配图或固定图数, 一句话足够的内容不强行画图.

| 要讲清的内容 | 默认表达方式 |
| --- | --- |
| 流程, 多方交互, 层级和关系 | Mermaid 流程图, 时序图或分类图 |
| 空间布局, 几何关系, Mermaid 难以清晰表达的示意 | SVG 空间示意图 |
| 少量数值比较 | 表格, 保留单位和比较条件 |
| 原因, 背景或简单边界 | 简短段落或清单 |

每张图只回答一个明确问题, 使用简短中文标签, 说明箭头含义, 突出关键变化, 不把长段落塞进节点. 图过于复杂时拆分. 理论论文可以用条件关系图, 综述可以用分类图, 不硬套系统流程.

报告优先直接展示图. Mermaid 使用客户端支持的图示代码块, SVG 通过图片或可查看文件交付, 不用大段源码代替图示. 在已有工具支持时预览并检查文字, 连线与布局; 未预览时不声称已验证渲染. 报告模板包含缓存前后对比的 Mermaid 示例和附近范围的 SVG 示例, 两者均为教学假设, 不作为任何论文的事实复用.

这些部分围绕同一个场景或研究问题连贯讲解. 术语先解释意思和作用, 再给名称, 必要时保留英文便于回查. 即使只有摘要, 也可补足必要的一般概念解释, 但会与论文的具体实现区分, 不由常识推断本文细节. 类比会说明对应关系, 在关键差异处说明不能照搬之处; 没有贴切类比时采用具体例子或分步说明. 教学用的假设场景会明确标注, 不冒充论文案例或证据.

关键判断旁附真实的论文定位. 图示明确区分论文原图, 根据原文重绘的示意图和教学假设图; 原图和重绘图就近附依据, 重绘注明影响理解的简化. 不添加未经确认的角色, 步骤, 因果关系或数值. 重要图表放在对应讲解中解释怎么看, 不单独凑章节. 用户提供研究目标时, 在相关讲解中结合目标判断. 不再要求旧版的固定 12 节结构, 英文推荐等级或单独的研究关联小节.

## 调用示例

### 没有领域基础, 提供 PDF

```text
使用 $paper-first-pass 阅读这篇论文: ~/Downloads/some-paper.pdf
我不了解这个领域. 请用具体例子解释它解决了什么问题, 为什么这个办法可能有用.
```

即使不补充第二句话, 也默认面向没有领域基础的读者, 以图为主, 短文补充. 预期结果是四部分的图文讲解, 用图解释适合图示的关系, 必要概念在出现时解释, 类比帮助理解但不替代原文证据, 不因压缩文字而省略原因和关键条件.

### 提供 arXiv 链接并附研究方向

```text
使用 $paper-first-pass 阅读这篇论文: https://arxiv.org/abs/XXXX.XXXXX
我目前在做检索增强生成的评测方向, 帮我判断这篇论文是否值得精读.
```

预期结果是先获取实际论文内容, 再生成报告. 在相关讲解中结合该方向判断论文是否值得精读, 用已确认的相关章节或图表支持判断; 不把第一遍的理解当作已经完成实验审计. 用户要求判断是否值得精读, 不等同于要求后续阅读建议.

### 已有基础, 快速筛选文献

```text
使用 $paper-first-pass 阅读这篇论文. 我已了解这个领域的常用方法, 想先判断它与已有工作有什么区别, 是否值得继续读.
```

预期结果是减少用户已掌握的背景解释, 保留核心变化, 证据与限制, 仍按第一遍的范围判断, 不自动进入完整精读.

### 目前只有摘要

```text
使用 $paper-first-pass 帮我理解这篇论文. 目前只有以下标题和摘要: ...
```

预期结果是明确标注只读到摘要, 将结果写成作者在摘要中的表述. 图也仅表达摘要支持的关系, 不从技术名称补全实现流程. 通用概念可单独画成教学示意, 明确不代表本文实现. 缺少实验设置, 证明或限制说明时如实指出, 不编造图表编号, 不把未读到写成作者没有做.

## 异常处理与边界

+ PDF 内容解析失败或链接内容获取失败时, 明确指出失败并停止, 不根据标题或记忆继续输出论文报告.
+ 提供的不是论文或可识别的论文片段, 例如博客, 新闻或课程笔记, 则说明不适用并停止, 不强行套用模板.
+ 理论, 综述, 评测或数据集论文按实际贡献和证据组织内容, 不硬凑训练过程或性能实验. 没有检查完整证明时不会声称已经验证证明.
+ 关键判断无法定位时如实说明, 不伪造页码或图表编号. 作者主张, 论文证据与自己的判断分开表述.
+ 完整实验审计, 逐行证明, 算法实现或复现不属于第一遍范围, 应根据需求进入第二遍或第三遍阅读.
